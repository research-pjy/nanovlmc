# L40S: first Thinking-model diagnostic

The machine `rama` runs directly in Conda environment `qwen-vl`, without Slurm or
Ollama. Its existing cached teacher is **Qwen/Qwen3-VL-8B-Thinking**, revision
`92f3c4b4feadd3a016ef468d103bb5f58b2a2c6b`. This diagnostic uses that exact offline
snapshot with BF16 on CUDA device 0, SDPA attention and batch size one. It never
loads or inspects the earlier user-created Python scripts. No package changes or
model downloads are performed.

This is a **caption-only** test: five original COCO references are the teacher's
input, not pixels. It tests reasoning exhaustion, EOS, output decoding, and caption
format. It does **not** reproduce image-conditioned failures or certify image
loading. Image-assisted generation remains a separate decision.

## Run only five training examples

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
python -m data_creation.diagnose_transformers run \
  --selection /home/jayanth/datasets/nanovlm-caption-work/selections-v1/development.json \
  --output /home/jayanth/datasets/nanovlm-caption-work/thinking-diagnostic-v1 \
  --count 5 --max-new-tokens 1024 --seconds-per-record 120
```

The default snapshot resolves from your home directory to the exact model path
reported in your inventory. No images are needed for this command. The first five
records of our fixed development selection are used; all are training records.
Held-out, confirmation and full pilot bundles are rejected for this diagnostic.

The 1,024-token cap includes **reasoning plus final text**, even though the requested
description is 20–25 words. It is a diagnostic budget, not an established production
setting. Greedy decoding, seed 42 and repetition penalty 1.0 are explicit; inherited
generation configuration and exact package versions are recorded. No claim of
optimal Thinking-model decoding is made.

The 120-second budget is checked between generation steps, not a hard process kill;
model loading and a stalled GPU kernel can take longer. Ctrl-C requests a stop at
the next generation stopping check, saves the current result and exits 75. An OOM
or other exception is recorded and stops immediately. Do not repeatedly rerun an
OOM without inspecting it.

Each record is atomically saved separately. Repeating the exact command skips
already recorded IDs, including recorded failures, and continues pending IDs.
An abrupt termination may lose only an in-flight record. Diagnostic retries or
changed budgets belong in a **new output directory**, preserving earlier evidence.
This diagnostic does not share a production generation run directory.

## Read the result

```bash
cat /home/jayanth/datasets/nanovlm-caption-work/thinking-diagnostic-v1/summary.json
```

Send the summary back first. Each `<image_id>.json` contains the reference captions,
exact text and rendered chat prompt, input/generated token IDs, raw decoding with
special tokens, decoding without special tokens, EOS IDs, stop classification,
candidate description and validation errors, timing and peak GPU allocation.
`runtime.json` records the environment and model generation defaults.
`diagnostic_identity.json` records the snapshot revision, weight sizes/blob names,
metadata hashes, source/config fingerprint, exact selected records and decoding.
Weights are not rehashed in full; cache identities do not prove weight integrity.

Possible output states:

- `empty_output`: no substantive decoded generation.
- `no_final_boundary`: no closing `</think>` found. This could be unfinished
  reasoning or unexpected output formatting; inspect the raw record. It is not
  automatically classified as a refusal or accepted as a caption.
- `empty_after_thinking`: reasoning closed, but no final text followed.
- `final_candidate`: final text exists; see separate length/format checks.
- `runtime_error`: an exception occurred; the traceback is retained.

Stop reasons distinguish EOS, token limit, time limit, user interruption and unknown
termination. A final-looking caption cut off by a limit still fails mechanical
acceptance. Semantic accuracy always requires review against the five references.
No diagnostic output is eligible for training export or production recipe freezing.

If loading fails, share `load_error.json`. If generation fails, share the summary
and the failing image's JSON. No old script is needed to investigate either case.

After reviewing the five results, we can compare a larger token budget on the exact
same IDs or evaluate Instruct, then extend to 40 training examples. Do not launch
28,100 generations based solely on a successful process exit. A direct Transformers
production backend, batching, human review integration and final export remain the
next stage after these diagnostics establish the correct generation behavior.
